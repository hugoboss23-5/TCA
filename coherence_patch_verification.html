1. Coherence Detector — Direct-Edge Discount

The Question

Does compute_phase_coherence() actually discount directly-connected node pairs? If not, it's just measuring activation propagation — which spreading activation already does.

The Code

def _has_direct_edge(graph: TopologicalGraph,
                     id_a: str, id_b: str) -> bool:
    """Check if a direct edge exists between two nodes (either direction)."""
    node_a = graph.get_node(id_a)
    node_b = graph.get_node(id_b)
    if node_a is not None and id_b in node_a.edges:
        return True
    if node_b is not None and id_a in node_b.edges:
        return True
    return False

The Discount Factor

Factor: 0.3
If two nodes share a direct edge (checked bidirectionally via _has_direct_edge), their Pearson correlation is multiplied by 0.3. This means:
  • A directly-connected pair with perfect correlation (r=1.0) contributes only 0.3 to the mean.
  • An indirectly-connected pair with perfect correlation (r=1.0) contributes the full 1.0.
Emergent sync is weighted 3.3× more than forced sync.

Why This Works

Consider two scenarios with identical Pearson correlations:

Complete graph (all forced sync): 6 nodes, every pair connected. All 15 pairs have direct edges. Every correlation gets ×0.3. If all r=1.0, coherence = 0.3.

Two clusters + one bridge (emergent sync): A–B–C and D–E–F, bridge B→E. Within-cluster pairs (A-B, B-C, A-C, D-E, E-F, D-F) = 6 pairs, all direct-edge, all ×0.3. Cross-cluster pairs (A-D, A-E, A-F, B-D, B-F, C-D, C-E, C-F) = 8 pairs with no direct edge (except B-E which has the bridge). So 7 of 8 cross-cluster pairs keep full correlation weight. If cross-cluster sync emerges through the bridge, those 7 undiscounted pairs dominate the mean.

The complete graph produces lower coherence than the bridge graph, even with identical activation patterns. That's the point: forced sync isn't insight.

The Pearson Implementation

def _pearson(xs: list[float], ys: list[float]) -> float:
    """Pearson correlation coefficient between two equal-length series.

    Returns 0.0 if either series has zero variance (constant).
    """
    n = len(xs)
    if n < 2:
        return 0.0

    mean_x = sum(xs) / n
    mean_y = sum(ys) / n

    num = 0.0
    den_x = 0.0
    den_y = 0.0
    for i in range(n):
        dx = xs[i] - mean_x
        dy = ys[i] - mean_y
        num += dx * dy
        den_x += dx * dx
        den_y += dy * dy

    denom = math.sqrt(den_x * den_y)
    if denom < 1e-12:
        return 0.0
    return num / denom
Why Pearson and not the existing compute_synchronization?
The existing function in temporal_node.py uses direction-agreement (did both go up? did both go down?). This is binary. Pearson captures magnitude of co-movement — two nodes that oscillate with the same amplitude and phase get r≈1.0, while two nodes that move in the same direction but with wildly different magnitudes get lower r. Phase coherence requires magnitude awareness.

def test_resonance(node: TopologicalNode,
                   signal_source: SignalSource,
                   graph: TopologicalGraph) -> float:
    """THE CORE GROUNDING PRIMITIVE.

    Instead of predict -> check -> update, we ask:
    "Is this node's position in the graph IN PHASE with the signal?"

    1. Derive prediction from topology (what do the edges claim?)
    2. Measure reality via signal source

    4. Update graph based on alignment

def compute_alignment(prediction: dict, signal: dict) -> float:
    source_type = signal.get("source_type", "")

    if source_type == "filesystem":
        signal_positive = signal.get("exists", False)
    elif source_type == "code":
        signal_positive = signal.get("success", False)
    else:
        # Generic: look for any truthy value in signal.
        signal_positive = any(
            v for k, v in signal.items() if k != "source_type"
        )

    pred_positive = prediction.get("predicted_positive", True)
    pred_confidence = prediction.get("confidence", 0.5)

    if pred_positive == signal_positive:
        return 0.5 + 0.5 * pred_confidence
    else:
        return 0.5 - 0.5 * pred_confidence
The else branch (lines 104–108) is the hardware escape hatch.
A WattyNode source returning {"coherent": True, "source_type": "biometric"} hits the else branch. any(v for k, v in signal.items() if k != "source_type") finds the truthy "coherent": True value. No TCA code needs to change.

A ReceiverSource returning {"resonant": True, "frequency": 7.83, "source_type": "receiver"} also hits else and works. The contract is: include at least one truthy/falsy value in your dict. That's it.
